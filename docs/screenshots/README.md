# Screenshots

`dashboard-suggested.png` shows the desktop app's mock-tier dashboard (the
e2e scenario's invented mods) at 1280x800, light theme, with the first-run
notice dismissed, the recommended rules imported (step 1 done), Suggested
selected and Apply as the current step.

The `mods-page/` images show the Mods page's activate/deactivate and
rescan flows, including the Apply dialog, as embedded in
[`docs/desktop.md`](../desktop.md). They are mock-tier captures at the
same size, dark theme.

Every image here is generated by
`apps/desktop/e2e/screenshots/docs.spec.ts`, which drives the mock-IPC
scenario (`apps/desktop/e2e/fixtures/scenario.ts`) into each state. From
`apps/desktop`:

```sh
RIMMERGE_DOCS_SCREENSHOTS=1 bun run e2e:screenshots -- docs.spec.ts
```

In PowerShell, set the variable for the run and clear it afterwards, so a
later locale-tour run in the same window does not regenerate the docs
images too:

```powershell
$env:RIMMERGE_DOCS_SCREENSHOTS = "1"; bun run e2e:screenshots -- docs.spec.ts; Remove-Item Env:RIMMERGE_DOCS_SCREENSHOTS
```

The spec is skipped without that variable and is not part of `bun run e2e`.
It uses the same dedicated port (5183) as `bun run e2e` and the locale
tour, so never run it at the same time as either. Two runs on the same
machine write identical files (font rendering differs between machines);
commit the PNGs it changes along with the UI change that caused them.
